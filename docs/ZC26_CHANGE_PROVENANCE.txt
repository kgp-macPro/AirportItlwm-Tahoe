STORE-PUBLICATION CONTRACT (independent of cache policy)
All FOUR existing helper uses remain at the same locations: packet mapped and
conventional after payload/control/bytecount stores before WRPTR; default TXqueue
after initialized/reset backing before its MMIO publication; dynamicTVQM after
all allocation/address/config stores before queue-enable firmware command.
No helper caller uses it for DMA-read visibility or a CPU StoreLoad handshake.
Use x86_64 volatile SFENCE with a full compiler memory clobber. It orders prior
stores before following stores; it does NOT order loads and does NOT prove DMA
completion. All lifecycle/token/admission/command atomics and their original
memory orders remain unchanged. Non-x86 fallback remains SEQ_CST; no new device
or DMA qualification. x86_64 baseline supports SFENCE without SIMD register use.

Primary reference: Intel SDM Vol2B SFENCE, document325383, page4-616:
https://cdrdv2-public.intel.com/782156/325383-sdm-vol-2abcd.pdf
Linux DMA memory-ordering contract reference (not code imported):
https://kernel.org/doc/html/latest/core-api/wrappers/memory-barriers.html
SFENCE is selected from the actual write-publication contract, not as a cache
flush, reduced correctness fence or guarantee of580Mbps. Existing lock-prefixed
ownership/counter operations still exist and may dominate cost. No numerical
speedup is inferred from instruction counts. Negative23/24/25 physical results
remain constraints: prior generic batching/store-width/cache choices did not
establish a solution; this is a coordinated, independently source-backed design.

INDEPENDENT COMMAND-STATUS CORRECTNESS REPAIR
A status helper receiving a nonnullfailed CPU response returnedEIO before freeing
its caller-owned response, unlike the bad-length branch. Free it on the same
failure branch, nullable/idempotent API as before. Current ordinary RX handlers
already filter CMD_FAILED responses before caller transfer, so this branch's
production reachability is NOT established. Do not call it an observed leak.
Transport-error ownership is unchanged: iwx_send_cmd transfers resp_pkt only on
successful wait, otherwise retains/frees its own response; command DMA ownership
and positive completion/quarantine never depend on this CPU response free.

Two SOURCE-PROVEN caller failures are fixed: iwx_add_sta_cmd set STA_ACTIVE when
transport err!=0 due to its compound if/else; it now returns the transport error
without asserting activation. iwx_add_aux_sta enabled an auxiliary queue after
transport error and replaced it with the queue-enable result; now returns error
before enabling. FirmwareADD_STA status failure remainsEIO; versions>=12 still
skip the legacy auxiliary path. Existing active bit is preserved on failedupdate,
not blindly cleared. All failures flow to existing initialization/recovery code.
These branches exist directly in frozenZC8 too. They are independent correctness
repairs, not an explanation of the ZC13chronology or a provenRX/firststatefix.
Actualhelper/PDU/free/fullaux/criticalstationtail tests inject both errno signs,
failed/short/missing/validresponse, FWstatuses and versions. No rate, queue-growth,
firmware binary, power policy or DMA-lifetime change.
